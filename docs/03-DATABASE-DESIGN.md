# 03 — Database Design

|         |                                                                                                             |
| ------- | ----------------------------------------------------------------------------------------------------------- |
| Status  | **Implemented tables only** (R0 milestone 1). Entities for later releases are added here as they are built. |
| Related | `02-SOFTWARE-ARCHITECTURE.md` §5 (tenancy), §7 (money)                                                      |

PostgreSQL 16. Schema in `src/server/db/schema.ts`; migrations are reviewed SQL files in `drizzle/`.

## Roles

| Role              | Used by                     | Privileges                                                        |
| ----------------- | --------------------------- | ----------------------------------------------------------------- |
| `edubridge_owner` | migrations, seed, operators | Owns all objects. Still subject to RLS on forced tables.          |
| `edubridge_app`   | the running application     | Explicit grants only; cannot bypass RLS; no DELETE on audit data. |

## Tables

| Table            | Scope  | Notes                                                                                                                                                               |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tenants`        | global | Schools. Readable by slug; the app may only update the current tenant's name, timezone and `mfa_required_roles` (two-step policy). `is_demo` marks a demonstration school (set only by `npm run demo:school`).                                                                              |
| `users`          | global | Identities. One user can belong to several schools. `citext` email; optional E.164 `phone`, stored only once verified by SMS (unique).                                                                                                 |
| `sessions`       | global | `id` = SHA-256 of the session token.                                                                                                                                |
| `login_attempts` | global | Failed sign-ins for throttling. Safe to purge rows older than 15 minutes.                                                                                           |
| `user_mfa`, `mfa_recovery_codes`, `mfa_challenges` | global | TOTP seed sealed with AES-256-GCM (`MFA_ENCRYPTION_KEY`); last accepted step stored to block replays; recovery codes and challenge tokens stored as SHA-256. |
| `notification_outbox` | global | Email/SMS written in the business transaction; claimed with `FOR UPDATE SKIP LOCKED`; retried with backoff (5 attempts); payload cleared after sending or giving up. SMS `segments` worked out when queued (1–20); an optional `idempotency_key` is unique per channel and recipient. `whatsapp_allowed` (the school's plan lets this family SMS go by WhatsApp), `sent_via` (sms or whatsapp), and `delivered_at`/`read_at` from WhatsApp's webhook (NOT-07). |
| `phone_verifications` | global | 6-digit SMS codes (hashed with the verification id), 10 minutes, 5 attempts, 3 per user per hour. |
| `password_resets` | global | 30-minute, single-use, hashed tokens; 3 requests per account and 20 per IP per hour. |
| `tenant_entitlements` | tenant | The school's plan, written only by platform administrators (RLS): plan name, campus, active-student and monthly SMS limits, `features text[]` (modules included, checked on every request), and the subscription record (status, billing period, trial end, paid until, price, notes). `mobile_money_provider` (paystack, mock or none; null: the deployment default) is set by platform staff (PAY-06). `plan_preset_id`: the preset the plan was last set from (a copy, not a link). `status_auto`: the status was last set by the automatic rules (SUB-05); `subscription_apply_automatic_status` (SECURITY DEFINER, for the school whose context is set only, through an update policy for the owner role) applies those rules. |
| `plan_presets` | global | EduBridge's plans (SUB-01): name, description, modules, limits, billing period and usual price in a currency. Readable by everyone; only platform administrators add, change or archive them (RLS); none is deleted. |
| `plan_change_requests` | tenant | A school asking for a plan change (SUB-02): preset and/or message, requested by, then approved, declined (with a note) or withdrawn, once (trigger); one waiting per school (partial unique index). Platform administrators read every school's. `kind` (`plan`, `add_module`, `cancel_module`) and `module` (SUB-08): approving an add request adds the module from today at the catalogue price; approving a cancellation ends the add-on at the end of the paid period. |
| `school_modules` | tenant | Modules a school has beyond its plan (SUB-06, ADR 0003): add-on, trial, promotion or agreement, first and last day, agreed price (flat or per active student, per billing period, in the school's currency) and note. Written only by platform administrators (RLS); never deleted; the end date is set once and a grant is ended once with a reason (trigger), so the rows are the school's entitlement history. |
| `module_release_access` | tenant | Schools allowed to reach a module that is in internal testing, ready or pilot (REL-02); separate from entitlements. One open row per school and module; ended once, never deleted. |
| `catalog_prices` | global | EduBridge's catalogue prices (SUB-07) for a plan preset or a module, per billing period and currency, flat or per active student. Readable by every school; only platform administrators add or archive them; a new price archives the one it replaces (archive once, trigger). |
| `staff`, `staff_departments`, `staff_positions` | tenant | Staff and HR (R4-1, module `staff_hr`): a person who works at the school, with or without an account (`membership_id`, one staff record per member), staff number from `tenant_counters` (S0001), personal details, emergency contact, current employment (type, department, position, campus, started, status, left on and why). No government identifiers. Departments and positions are the school's lists, archived not deleted. Composite foreign keys to memberships, campuses and the lists. |
| `staff_employment_events` | tenant | Every employment change (started, changed, left, returned) with its effective date, who recorded it and a note. Insert-only for every role (statement trigger). |
| `leave_types`, `leave_requests` | tenant | Leave types (days a year or no limit, paid or unpaid; archived). Requests: person, type, first and last day, working days when asked, reason, status. A trigger allows only waiting to approved, declined or cancelled, and approved to cancelled; the decision is made once and the request itself never changes; nothing is deleted. |
| `pay_components` | tenant | Payroll (R4-2, module `payroll`): the school's earnings, deductions and employer contributions, each fixed or a percentage of basic or gross (an earning never of gross, by a check). No rates are stored here; kind and basis never change after creation. Archived, not deleted. |
| `staff_salaries`, `staff_salary_components` | tenant | A person's salary from a month: basic (minor units) and each component's amount (minor units) or percentage (basis points). Insert-only for every role (statement triggers); the salary in force for a month is the latest effective on or before it. |
| `payroll_runs`, `payroll_lines` | tenant | A month's payroll: draft, then approved (Proprietor) or cancelled, once (trigger); one live run per school and month (partial unique index). Lines hold each person's basic, gross, deductions, net, employer contributions and a frozen copy of the items; they can be replaced only while the run is a draft (trigger), and `net = gross - deductions` is checked. |
| `payroll_adjustments` | tenant | One-off earnings or deductions for a person from a month, applied once to the first approved run that includes them, or cancelled once (trigger); never rewritten or deleted. |
| `safeguarding_leads` | tenant | Safeguarding (R4-3): the school's designated leads, appointed and ended (once) by the Proprietor; never deleted. `app_is_safeguarding_lead()` reads it for the policies below. |
| `safeguarding_cases` | tenant | A concern about a student: reference (SG0001), category, the reporter's account (never changes: column grants allow only status, assigned lead and updated time), status open, monitoring or closed. Read only by leads, or by the reporter for their own report (RLS); never deleted. |
| `boarding_houses`, `boarding_rooms`, `boarding_beds` | tenant | Boarding (R4-8): houses (boys, girls or mixed), their rooms and numbered beds; archived, never deleted. |
| `boarding_house_staff` | tenant | Members appointed to look after a house, ended once; while appointed they get `boarding.view` and `boarding.exeat` as a school grant, for that house. |
| `boarding_assignments` | tenant | A boarder's bed for a term: one open per boarder and term and one per bed and term (partial unique indexes); ended once, never deleted. Term billing charges the boarding item to students with one. |
| `boarding_exeats`, `boarding_settings` | tenant | A boarder signed out (why, who collected them, due back) and back in once; one open per boarder; never deleted. The school's boarding fee item. |
| `finance_check_reviews` | tenant | Finance checks (R5-2): a flag looked at, once, with a note and who; the key names the flag and its facts, so changed facts make a new flag. Insert-only. |
| `early_warning_rules` | tenant | Early warning (R5-3): one row per school, the four rules on or off with their thresholds (suggested defaults until changed). |
| `early_warning_reviews` | tenant | A teacher's review of an indicator, once: no action, support plan (linked) or referred, with a reason; the key names the rule, student and stretch. Insert-only. |
| `support_plans`, `support_plan_updates` | tenant | A student's support plan (goal, actions, who, review date), closed once with an outcome, never edited or deleted; updates added with an optional new review date, insert-only. |
| `ai_feature_flags` | platform | AI gateway (R5-4): one switch per AI task, set by platform staff, under the global switch in `platform_settings` (with the provider, model, address, approval and limits). |
| `ai_school_limits` | tenant | A school's own AI allowance (tokens a month, requests an hour, tokens a day), set by platform staff; empty keeps the platform default. |
| `ai_usage` | tenant | Every AI call and every attempt a limit stopped: person, request, task, provider, model, tokens, estimated cost, outcome, time. Insert-only. |
| `ai_platform_months` | platform | Tokens across every school, by month: totals only, for the platform limit. |
| `ai_drafts` | tenant | AI drafting (R5-5): who asked, the task, provider and model, what was sent (no names), the drafts, and the outcome (used, changed or discarded), decided once; never deleted. |
| `library_titles`, `library_copies` | tenant | Library (R4-7): books (one per ISBN, checked) and their copies, numbered from a per-school counter (B0001) that never changes. Archived or withdrawn once with a reason, never deleted. |
| `library_loans` | tenant | A copy lent to exactly one borrower (a student or a member of staff), due on a day; one open loan per copy (partial unique index). Renewed while open; returned or lost once, then never changed. A late student's fine and the ledger entry that charged it (billing key `library:<loan>`). |
| `library_reservations`, `library_settings` | tenant | A borrower waiting for a title, then holding a returned copy (one hold per copy), then collected or cancelled; only forward. The school's loan period, books at once and fines (per day, maximum). |
| `inventory_suppliers`, `stock_items` | tenant | Inventory (R4-6): suppliers, and things kept in stock (unit, reorder level). Archived, never deleted. |
| `stock_movements` | tenant | Received (positive, optional supplier, unit cost and purchase request), issued (negative, to whom) or a count correction (with a reason). On hand is their sum. Insert-only. |
| `assets`, `asset_events` | tenant | The asset register: tag from a per-school counter (A0001), location, custodian (member or name), condition, cost, supplier; disposed once with a reason and never changed after. Every move, hand-over and condition change is an insert-only event. |
| `purchase_requests`, `purchase_request_lines` | tenant | PR0001: what is asked for, as lines with quantity and estimated unit price (minor units), optionally a stock item. Decided once by someone other than the person asking (check); statuses only move forward (trigger); what arrived is recorded once per line. |
| `maintenance_requests`, `maintenance_updates` | tenant | MR0001: what needs fixing, where, urgency, optional asset; open, in progress, done or cancelled, done and cancelled final. Every change is an insert-only update with who and when. |
| `transport_vehicles`, `transport_routes`, `transport_stops` | tenant | Transport (R4-5): vehicles (driver and attendant as names and phones, no account needed), routes with a vehicle and a fare per term, and stops in order with morning and afternoon times and an optional fare of their own (minor units). Archived, never deleted (no DELETE grant). |
| `transport_assignments` | tenant | The route and stop a student rides in a term, both ways or one way. One open assignment per student and term (partial unique index); the stop must be on the route (composite foreign key). Ended once, never changed or deleted; term billing charges the transport fee item from the open ones. |
| `transport_settings` | tenant | Which optional fee item transport is billed as, and whether families get a push when their child boards or gets off. |
| `transport_trips`, `transport_trip_marks` | tenant | One run of a route per day and direction (with that day's vehicle), and each child on it: boarded (time, who), then got off once. Marks are never changed or deleted (column grants and a trigger). |
| `visitor_visits` | tenant | Visitors and pickup (R4-4): a visitor signed in (name, optional phone and organisation, purpose, the member visited or a written name, campus, badge, note, who signed them in and when). Signed out once; nothing else changes and visits are never deleted (column grants and a trigger). |
| `pickup_collectors` | tenant | Someone other than a guardian who may collect a child (name, relationship, optional phone, photo as a stored file, last day, note). Ended once with a reason; never deleted. Guardians who may collect are the `can_pick_up` flag on `student_guardians`, not copied here. |
| `pickups` | tenant | A child released to a guardian or named collector (exactly one), or a refusal with the person's name and why (check constraint), on the school's local day; the person's name and relationship kept as they were. Cancelled once with a reason; otherwise never changed or deleted. |
| `safeguarding_entries`, `safeguarding_access`, `safeguarding_documents` | tenant | A case's history (notes, actions done once, referrals, contact with the family, meetings, status and lead changes; insert-only), every opening and download by a lead (insert-only), and confidential documents (removed once, never deleted). All three readable and writable by leads only (RLS). |
| `staff_attendance` | tenant | One mark per person per day (present, late, absent, off duty) with a version; each change must step the version by one (trigger), so a change made from an old copy cannot land. Corrections are audited with before and after. |
| `sms_usage` | tenant | One row per SMS charged to a school (fee reminders, payment receipts, absence SMS, announcements, consent forms and event reminders, with `student_id` where the SMS is about one student; parent sign-in codes, one row per school with the number and `shared_with` the count). Insert-only (no update policy; triggers refuse UPDATE, DELETE, TRUNCATE); delivery comes from the linked `notification_outbox` row. Codes are recorded through `record_parent_code_usage`, which checks the message was just queued and not already recorded. `segments` is copied from the queued message by a trigger (never from the caller); limits and charges count segments. |
| `subscription_invoices` | tenant | EduBridge's invoices to a school: number `EB-YYYY-nnnnnn` (sequence), frozen lines (JSON) and total, period, issue and due dates. Platform administrators issue them; the school reads its own. A trigger allows only marking paid or void, once. |
| `term_moves`, `term_move_enrolments` | tenant | A move of students from one term's classes into another's, with the placements it created and the students it graduated. Written once; the only change is marking it undone (once, trigger). |
| `platform_settings` | global | One row: default SMS price, grace days, days a module stays read-only after an add-on ends (`module_read_only_days`, R4), and what EduBridge invoices print (issuer details, how to pay). Readable by the app; only platform administrators update it (RLS). |
| `school_holidays` | tenant | Days a school is closed within its terms; registers are refused on them. Added and removed by academic leads (audited). |
| `absence_alert_settings`, `absence_alerts` | tenant | Whether and when families get an absence SMS (days in a row, days in a term), and every alert sent (insert-only; one per student per run of absences and per term total). |
| `school_preferences`, `sibling_discount_rules` | tenant | A school's choices (also branding, offline receipts, discount approval thresholds, assistant, admission number format, starter template, teaching model, report-card layout, lesson attendance, online applications and admission fees): whether Accountants may void receipts, the overview's collection-rate basis and attendance follow-up threshold, payment receipt SMS and automatic reminders (interval, minimum, last run day), and contact details for families; and its sibling discount rule (who pays in full, discounts by place, fee item). |
| `announcements`, `announcement_reads` | tenant | Announcements to the school, a level, class or campus (`audience`, `audience_id`), with the number of SMS sent; insert-only (trigger). Reads: one row per announcement and parent number that opened it. |
| `support_grants`, `support_views` | tenant | Support access (PLT-02): the Proprietor's grants (until when, note; never deleted; `ended_at`/`ended_by_user_id` set once by a trigger and column grants; at most 7 days by a check) and every page or form support opened during one (insert-only). `audit_events.support_grant_id` tags changes support made, from the transaction setting `app.support_grant_id`. |
| `device_tokens` | global (per user) | API device tokens: SHA-256 of the token, name, last use, expiry (renewed in use), revocation; no delete by the app. |
| `sync_operations`, `sync_changes` | tenant | Sync protocol: each device operation recorded once with its outcome, in the same transaction as its effects (insert-only); the change feed written by triggers on students, enrolments, classes, attendance marks and assessment scores (purged after 90 days). |
| `learners` | global | Portable learner identity: an id only, no personal details. `students.learner_id` (set by a trigger, unique per school) and `students.left_reason`. |
| `learner_records`, `transfers`, `prior_records` | tenant (transfers: either school) | Transfer Passport: signed records as issued (revocable once), transfers moving only forward with the signed package fixed once attached, and records received from previous schools (insert-only, verified or not). |
| `assistant_queries` | tenant | Every assistant question with the tools it used, the answer, model and tokens; insert-only; tagged when asked by support. |
| `memberships`    | tenant | User ↔ school with `roles text[]` (validated by a check constraint). Never deleted by the app; suspend. A user can also see their own memberships in other schools. |
| `academic_years`, `terms` | tenant | School-local `date` columns. `EXCLUDE USING gist` blocks overlapping years/terms per school (`btree_gist`); a partial unique index allows one current term per school; terms reference years by composite FK. |
| `levels`, `classes` | tenant | Levels in promotion order with a stage (creche … jhs). Classes reference level, campus and optional class teacher by composite FKs (`(tenant_id, x_id)`); unique name per campus; archived, never deleted. |
| `students`, `enrolments`, `tenant_counters` | tenant | Minimal student data (names, sex, optional date of birth); admission number unique per school, auto-numbered from a per-school counter that skips numbers in use. One class per student per term (composite FKs to student, term, class). Teachers see only their classes' students. |
| `guardians`, `student_guardians` | tenant | One guardian per phone number per school (partial unique index), so siblings share guardians; phone or email required (E.164 check). Links carry relationship and a primary contact flag (one per student, partial unique index). `portal_blocked_at`/`portal_blocked_by_user_id` stop a guardian using the parent view (set and cleared together). A second SELECT policy shows guardian rows whose phone equals `app.parent_phone`, so parent sign-in can find the schools that have a number on file (migration 0039). |
| `fee_items`, `fee_structure_lines` | tenant | Fee items (unique name per school, archived, never deleted). Structure lines: amount in integer pesewas (`bigint`, check 0 – 1,000,000,000) per term, item and level, with an optional class override; `UNIQUE NULLS NOT DISTINCT (term, item, level, class)`. Billing will copy amounts into the ledger, so structure edits never change past bills. |
| `ledger_entries` | tenant | Append-only fee accounts: the app role has INSERT and SELECT only, and triggers refuse UPDATE, DELETE and TRUNCATE for every role. Signed integer pesewas (charges positive; payments and discounts negative; the balance is the sum), with a check tying sign to kind. A reversal must exactly negate one non-reversal entry of the same student (trigger) and each entry is reversed at most once (unique). `UNIQUE (tenant, student, billing_key)` makes term billing idempotent; `entry_number` (identity) orders statements. |
| `payments`, `payment_voids` | tenant | Insert-only (grants and triggers, as for the ledger). Receipt numbers `R000001…` unique per school, allocated from `tenant_counters` inside the payment transaction (no gaps); `UNIQUE (tenant, idempotency_key)` makes a double-submitted form record once. Each payment has exactly one ledger entry (partial unique index; a trigger checks student and amount). A void is a `payment_voids` row plus a reversal of that entry. |
| `fee_concessions` | tenant | Per-student scholarship or discount: basis points (1–10000) of one item or every item, or a fixed pesewa amount off one item (checks enforce exactly one kind). Can be ended, never deleted. Billing adds `discount` ledger entries keyed `discount:<concession>:term:<term>:item:<item>`, capped at the live charge. |
| `payment_plans`, `payment_plan_instalments` | tenant | Instalment schedule per student (one active, partial unique index); cancelled, never edited; instalments insert-only. Progress is computed from payments (not voided) recorded after the plan was created; the ledger is not touched. |
| `mobile_money_requests` | tenant | One row per Mobile Money prompt: provider, network, E.164 phone (any country; checked against the school's country by the service), amount and the school's currency (ISO code) and an idempotency key (unique per school). One pending prompt per student (partial unique index). The app may UPDATE, but a trigger keeps what was asked for unchanged, sets the provider reference once and the outcome once (only `pending` and `expired` can still change; never back to pending), and refuses DELETE and TRUNCATE. `successful` requires `payment_id`, and a trigger checks that payment is Mobile Money for the same student and amount. |
| `mobile_money_callbacks` | tenant | Provider callbacks, stored before processing: request id and/or provider reference, SHA-256 of the body (unique per school and provider, so retries are stored once; the raw body is not kept), attempts, and the result once processed. The app may only update `attempts`, `processed_at` and `result`; a processed row cannot change; no DELETE or TRUNCATE. Requests also carry a one-time review (`reviewed_at`, `reviewed_by_user_id`, `review_note`), allowed only on `needs_review` and set once (check and trigger). |
| `parent_sign_in_codes` | global | Parent SMS codes (hashed with the request id), 10 minutes, 5 attempts; `tenant_ids` are the schools that had the number (empty: unknown number, no SMS). Used for limits per number (3 per 15 minutes, 10 a day), per network address (30 an hour) and per school (300 an hour). Only attempts and consumption can change; purged after 2 days. |
| `parent_sessions` | global | Parent sessions: `id` = SHA-256 of the token, the verified phone, 30 days renewed while in use. No tenant: what a parent sees is worked out per request from each school's guardians. |
| `push_subscriptions` | global | Web push on a parent's phone, or on a staff device (PSH-01: the staff sign-in and member instead of the parent sign-in and number; exactly one owner, check): endpoint (unique, https), keys, the number and the parent sign-in it belongs to (`ON DELETE CASCADE`: sign-out and expiry remove it), last sent. The app may update only the sign-in, number and keys (a browser re-subscribing under a new sign-in) and `last_sent_at`. |
| `whatsapp_contacts` | global | A family number's WhatsApp choice (WAB-01): when it opted in and out, and how (parent view or a STOP reply). The consent record. |
| `scheduled_announcements` | tenant | Announcements to post later (NOT-06): the announcement's fields, `send_at`, status (pending, posted with its announcement, cancelled) and a note; never changes once posted or cancelled (trigger). |
| `subscription_payments` | tenant | Online payments of EduBridge invoices (SUB-04): reference `EBI.{tenant}.{id}`, provider, amount and currency, status, provider reference; a succeeded payment never changes. `subscription_invoice_paid_online` (SECURITY DEFINER, the school in context only) marks the invoice paid when the payment covers it exactly, and extends paid until. |
| `balance_links` | tenant | Read-only links to one student's balance sent in fee reminders: student, guardian, recipient, token hash, 7-day expiry. Insert-only; readable in the tenant or by presenting the token (`app.balance_link_token_hash`). Valid only while the guardian still has that number, is linked to the student and is not blocked. |
| `fee_reminders` | tenant | SMS fee reminders sent: student, guardian, recipient (E.164), school day, balance at the time (also in the message), sender. Insert-only (grants and triggers); `UNIQUE (tenant, student, channel, sent_on)` allows one a day. The message itself is a `notification_outbox` row queued in the same transaction. |
| `subjects`, `level_subjects` | tenant | Subjects a school teaches (name unique per school) and the levels that take each, with report-card order. Taking a subject off a level keeps its marks. |
| `assessment_schemes` | tenant | One per term: the parts of a subject's mark (`components` JSON: key, name, weight %, out of; weights add up to 100) and whether report cards show positions. Saved by the school or by the first mark; until then the previous term's or the defaults apply. Fixed while any report card of the term is published. |
| `grading_scales` | tenant | A school's grade bands for a stage (JSON: lowest whole mark, grade, remark, and optional grade points in hundredths for a GPA). No row: the stage's defaults. |
| `assessment_scores` | tenant | One mark per term, student, subject and part, in integer tenths (37.5 → 375); cleared marks are deleted. A trigger refuses insert, update or delete while the student's report card for the term is published. Changes are audited with old and new marks. |
| `report_cards` | tenant | One per term and student: attitude, conduct, interest, days present/open (by hand until attendance), class and head teacher remarks; on publishing, `snapshot` (JSON) freezes everything the card shows. A trigger refuses any change to a published card except withdrawal to draft, which clears the snapshot (check). No DELETE. |
| `report_card_batches`, `report_card_files` | tenant | Bulk print runs: classes, status, attempts and a lease (`locked_until`) so one worker prints a run at a time and a crash resumes after the last class; one PDF per class (`bytea`, SHA-256, size). Removed after 7 days. Move the files to object storage when schools print often. |
| `attendance_registers` | tenant | One per class and school day (`UNIQUE (tenant, class, date)`), with its term and who last saved it. Never deleted; only `taken_by_user_id` and `updated_at` change. |
| `attendance_marks` | tenant | A student's mark on a register: status (present, late, absent, excused), optional reason (120 characters), `version` (a trigger allows only +1 per change, so stale offline changes are always detected). Never deleted. |
| `attendance_changes` | tenant | Insert-only history of every mark change (grants and triggers refuse UPDATE, DELETE, TRUNCATE): before and after, version, who, source (`online`, `offline`, `kept_mine`) and when it was recorded on the device. |
| `platform_secrets`, `platform_events` | global | Integration keys entered by platform staff (Admin, Integrations), sealed with `MFA_ENCRYPTION_KEY`; only a hint is ever shown. Platform events: who changed an integration, readable by platform administrators only (RLS). |
| `record_signing_keys` | global | Transfer Passport Ed25519 keys: public key (published), private key sealed, `active` or `retired` (one active, partial unique index). Retired keys stay so earlier records still verify; written only by platform administrators. |
| `finance_period_locks` | tenant | Closing the books (FIN-16): each close or reopen as a row (insert-only); `app_locked_through()` and a trigger on `ledger_entries` and `payments` refuse postings dated on or before the locked day, whatever writes them. |
| `refunds` | tenant | Refund workflow (FIN-10): requested, approved or rejected (by a second finance user when the school has one), paid (posts a `refund` ledger entry and the next refund number) or cancelled; a trigger lets status only move forward. |
| `student_fee_options` | tenant | Which students take an optional fee item (FIN-02); billing charges optional items only to them. |
| `stored_files` | tenant | Logos, student photos, student documents and payment evidence, as `bytea` in the database (covered by backups and RLS). Type decided from the bytes; limits per purpose; marked removed, never deleted (trigger). |
| `student_medical` | tenant | Medical and emergency information (SIS-06), one row per student; read and changed only through the service, which checks `students.medical` and records every view. |
| `reconciliation_runs`, `reconciliation_items` | tenant | Daily Mobile Money reconciliation (PAY-04): one run per school, provider and day (immutable), and the differences found; only the review (who, when, note) can be added later. |
| `subject_teachers` | tenant | Teaching by subject: the teacher of a subject in a class (one per class and subject; one teacher can teach a subject in many classes). Used only when the school's `teaching_model` is `subject`. |
| `timetable_periods` | tenant | The school day: named periods and breaks with school-local times (`HH:MM`, checked; ends after it starts; no overlaps, checked by the service). A period that lesson registers were taken in cannot be removed. |

## Tenant context

```ts
await withTenant(db(), { tenantId, userId }, async (tx) => {
  /* queries */
});
```

RLS policies compare `tenant_id` with `app_current_tenant_id()`, which reads the transaction-local
setting. Outside `withTenant`, tenant tables return nothing.

## Adding a tenant-owned table (checklist)

1. Add `tenant_id uuid not null references tenants(id)` and index queries that filter by it.
2. `npm run db:generate -- --name <change>` to create the table migration.
3. In a custom migration (`npx drizzle-kit generate --custom --name <change>_rls`):
   `ENABLE` + `FORCE ROW LEVEL SECURITY`, policies using `app_current_tenant_id()`, and only the
   grants the app needs for `edubridge_app`.
4. Run `npm test`; the isolation suite fails if RLS is missing.

## Conventions (from `02`)

- Money: `bigint` minor units + ISO 4217 code; append-only ledger; triggers block mutation of posted entries.
- Timestamps: `timestamptz`, displayed in the school's time zone.
- Tenant tables referencing other tenant tables use composite FKs `(tenant_id, x_id)`.

## Workflow

- Generate: `npm run db:generate -- --name <change>` (never edit an applied migration).
- Apply: `npm run db:migrate` (uses `MIGRATION_DATABASE_URL`).
- Destructive changes (drops, type narrowing) require product-owner approval and a backfill plan.
